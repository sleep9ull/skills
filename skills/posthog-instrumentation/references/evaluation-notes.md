# 验证范围与局限

日期：2026-11-02。当前 evaluation-cases.json 包含三个通用的隔离场景，用于生成最小补丁提案、契约和测试设计：

| 场景 | 检查内容 |
|---|---|
| 设置与业务边界 | 保持 logout、reset 后不误归属、删除仅意图、内存更新语义、先定义场景再写失败测试 |
| 曝光与购买隔离 | 原校验和导航不变、Gallery 七次曝光、URL 与可见性、无曝光点击、无 UI 重构 |
| 清理与来源 | 版本与索引、伪曝光、缺少来源载体、共享属性及其他渠道、模块排除 |

这些场景已去除项目专属名称、路径和协议。改写后的场景尚未重新进行使用 skill / 不使用 skill 的对照运行，因此不保留旧输入的分数，也不声称当前版本已通过语义评测或提升准确率。

结构检查覆盖元数据、相对引用和 JSON 格式；不能据此证明埋点实现正确。隔离提案的文本审阅也不能代替实际补丁编译和运行。

重新评测时，对相同输入分别运行使用 skill / 不使用 skill 的配置，保存提案、逐项证据和失败项。提示本身已经明确多数边界，对区分度有限；不能仅凭通过率宣称 skill 带来改进。报告运行次数和环境限制。

实际项目仍需验证业务行为不变，运行相关测试、构建、页面交互并核对 PostHog 接收。未执行的验证应明确记录；不要只检查关键词。
